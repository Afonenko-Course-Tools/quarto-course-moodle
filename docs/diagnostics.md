# Диагностика Moodle

Собственные ошибки оформлены как `ID: Moodle: смысл`, затем доступные источник,
объект, поле, связанные объекты и подсказка. Контекст относится к исходному
документу и объекту; строки временного JSON или готового XML не выдаются за строки
QMD. Ключи, поля и типы binding/Body остаются в исходном написании.

| Устойчивый ID | Смысл | Исправление |
| --- | --- | --- |
| `ADAPTER` | Некорректный teacher Body, binding, состав работы, ресурс или неподдерживаемое содержимое/тип ответа. Компонент Moodle и доступный объект/поле уточняют причину. | Исправьте исходный вопрос или binding; пересоздайте пакет актуальным Core. |
| `MOODLE.INPUT_INVALID` | CLI не получил путь пакета, binding или выходного XML. | Передайте три аргумента: `export.ts package.json binding.json bank.xml`. |

`ADAPTER` сохранён для всех прежних semantic guards; новая структура ошибки
не вводит дополнительные ID и не меняет правила принятия пакета. Для binding
`defaultGrade` должен быть положительным конечным числом, а `shuffle` — boolean.
При `single-choice` публичный ответ — один native BulletList с не менее чем двумя
вариантами. `closedKey.correct` — целый индекс от 0 до последнего варианта.
Moodle принимает только `manual` и `single-choice`. Для проверки хеша ресурса
используются фактические байты из `data`; ручное исправление `sha256` недопустимо.

Teacher Body включает `closedKey`, `solution` и `gradingNotes`; это отдельный
контракт относительно публичного пакета Print. Ключ используется для оценки
single-choice. Решения и заметки никогда не становятся XML-текстом. Публичные
условия/варианты проходят проверку native узлов и ссылок. Ресурсы принадлежат
пакету, имеют безопасные уникальные target и совпадающий SHA-256. Вложения
выбираются по точным Image/Link target, а не по упоминанию имени в тексте.

## Внешний инструмент и неизвестные ошибки

Отказ Quarto/Pandoc имеет имя `ExternalToolFailure`, сохраняет tool, exitCode,
stdout, stderr и исходную IO-причину, если она есть. Это внешний отказ, а не
semantic `ADAPTER`: прочитайте сохранённый вывод инструмента и исправьте причину
его запуска или обработки. Непустой stderr при успешном exit 0 допустим.
При ошибке запуска exitCode неизвестен; причина Deno остаётся доступной в cause.

Собственные ошибки имеют имя `ExtensionDiagnostic` и свойство `code`.
CLI выводит ожидаемую диагностику или внешний отказ один раз. Неизвестные
исключения, например SyntaxError повреждённого JSON или TypeError программной
ошибки, сохраняют исходный стек для расследования. Error-объекты локальны,
не сериализуются и не являются новым report API.

XML записывается после успешной валидации, проверки ресурсов и преобразования
всех фрагментов Pandoc. Отказ до записи не создаёт новый XML и не заменяет
предыдущий. Проверки охватывают повреждённый binding, choice mapping,
неподдерживаемый тип ответа, хеш ресурса, настоящий CLI и отказ внешнего процесса.
Отрицательные примеры находятся только в `tests`; авторская
[демонстрация](../examples/questions/README.md) содержит корректные вопросы.

Экспорт создаёт только банк вопросов. Он не создаёт Moodle Quiz/Assignment,
не устанавливает права доступа и не подтверждает импорт в реальную LMS.
